# 数据结构与系统架构优化实施计划

> 执行：当前会话并行实现独立模块，主开发集成与复查；用户已授权持续优化。每一步先补可复现回归，再实现和验证。

**目标：** 去除任务调度和交互中的历史全量扫描，建立可迁移、可分页、事务一致的数据访问边界，保留既有求解语义及API兼容性。

**架构：** 保持模块化单体：API/CLI → 应用服务 → 作业查询与状态规则、事件日志 → SQLite；数值子进程保持独立。JSON正文仍是实体事实来源，查询投影与正文同事务更新。事件以数据库为唯一事实来源，JSONL作为按需生成的快照。

**技术：** Python3.12、SQLite、FastAPI、React/TypeScript；不为本次优化增加外部服务依赖。

## 方案取舍

| 方案 | 取舍 | 决定 |
|---|---|---|
| 仅缓存旧列表 | 缓存失效与跨进程一致性复杂，仍需全量解析 | 不采用 |
| SQLite索引投影、查询仓储与游标分页 | 保留本地部署、旧正文与接口；迁移可事务回滚 | 本轮采用 |
| 全量关系表/外部数据库/服务拆分 | 可扩展空间更大，但当前单机单作业模型尚不需要其部署与迁移成本 | 后续按实测需求评估 |

## 1 存储与迁移

- [x] `emsolver/store.py`：schema版本2，显式稳定递增序号、status/project_id投影、组合索引；事务迁移保留旧rowid先后与JSON字节，未知未来版本拒绝写入。
- [x] 增加SQL计数、首条查询、受限选择、稳定上界的游标分页；旧`list/get/put`保持调用契约。分页游标绑定数据库实例及筛选条件，恢复到新实例后旧游标失效。
- [x] 新增`tests/test_store*.py`：旧库迁移、双连接同时启动、失败回滚、投影一致性、跨页插入、非法游标、查询计划和解码量上限。

## 2 应用领域边界

- [x] `emsolver/jobs.py`：任务状态枚举、合法转换、作业查询仓储；`Service`作为兼容入口，仅通过查询接口选择队首及计算配额。
- [x] 活跃作业恢复只查询活跃状态；状态终态不可回退；批次限额仍处于同一写事务。
- [x] `tests/test_job_queries.py`：禁止调度/配额调用全量任务列表；保留FIFO、取消、跨连接幂等、重试关联行为。

## 3 事件边界

- [x] `emsolver/events.py`：增量worker事件读取器，保留半行，进程退出后最后补读；事件数据库分页与原子JSONL导出。
- [x] `Service._event`取消数据库/文件同步双写；作业状态、事件和审计随数据库事务共同提交/回滚。报告只加载最近1000条事件，完整下载通过分批流式导出生成。
- [x] 回归：结束时末尾事件不丢、半行只导入一次、故障回滚无文件幽灵记录、导出快照与数据库一致。

## 4 接口与工作台

- [x] 增加`GET /api/v1/jobs/page`和`GET /api/v1/jobs/{id}/events/page`，保留旧列表；分页返回`items,next_cursor,total`，事件页返回`items,next_after,has_more`。
- [x] 新增`GET /api/v1/workspace/summary`返回SQL聚合总数；前端任务列表分页追加，统计使用总数，不把已加载页数当全局总量。
- [x] 前端按最后事件seq增量合并、终态最后同步后停止详情轮询；任务切换重置游标、取消旧请求，避免异步串流和重复事件。

## 5 集成与证据

- [x] 停止旧服务，创建SQLite备份和代码快照后再迁移真实本地库；不删除既有数据。
- [x] 旧/新备份恢复按原队列顺序重建已知schema；关联行分批读取并以一个目标写事务恢复。
- [x] 原91项及新增迁移/并发测试通过；前端生产构建通过；2万条历史任务实验记录解码量、查询计划及重复测量耗时，避免只报告单次加速比。
- [x] 浏览器跑通已有结果、真实新任务、增量事件及列表翻页；更新架构文档、覆盖登记和版本交付说明。

兼容边界：schema2数据库不支持交给旧版裸INSERT程序直接写入。回退使用迁移前SQLite备份及对应代码快照。分页保证固定入库上界且不重复返回同一序号；实体状态仍为查询时的当前值，不声称跨HTTP请求保持数据库事务快照。

# 多人协作与多机计算实施计划

> **For agentic workers:** 使用 subagent-driven-development 执行独立模块，主开发集成并复查。用户已确认多人协作、多台计算机器目标，继续实现与验证。

**Goal:** 保留现有工作台、项目权限、数值算法与验收口径，增加 PostgreSQL 服务端元数据、独立远程计算节点和可恢复的任务租约。

**Architecture:** API 管理身份、项目和权威任务状态；PostgreSQL 保存元数据和持久租约；工作节点通过鉴权 HTTP 下载冻结输入、执行独立求解子进程并回传结果。服务器重新验证结果，只有仍持有有效租约的尝试能够发布。API 与计算节点无需共享文件系统；同一 API 部署的文件存储保留本地受控目录。

**Tech Stack:** 现有 React/TypeScript/FastAPI；PostgreSQL、psycopg 3；httpx 远程节点；现有 NumPy/SciPy 与独立验证进程。

## 全局约束

- 真实业务库、矩阵、原发布归档先保留。开发测试使用独立 PostgreSQL 实例/命名空间和临时目录。
- 工作者凭据由管理员显式签发，只保存摘要；权限按节点项目范围和资源预算检查，撤销立即阻止后续领取/续租/提交。
- 同一任务同一时刻仅一个有效尝试；过期重试有次数上限；迟到结果拒绝；完成重试以摘要幂等；取消不得被成功结果覆盖。
- 冻结配置、输入哈希、求解方法和数值认证规则不放宽。服务器对成功/部分结果重新执行有界原问题验证。
- 凭据不得进入子进程、结果包、URL 或日志；远程明文 HTTP 只能由显式开发选项启用。
- 保留 SQLite 本地运行；PostgreSQL 通过可选依赖及显式环境配置启用，迁移仅允许写入空目标。
- 验证须区分本机两个进程/容器与两台真实物理机器，不宣称尚未执行的跨机器或性能验收。

## 模块与接口

| 所属 | 文件 | 职责 |
|---|---|---|
| 存储开发 | `postgres_store.py`、`persistence.py`、迁移脚本与 PG 测试 | PostgreSQL 事务、兼容查询、实例身份、SQLite 快照与只读源迁移 |
| 协调器开发 | `cluster.py`、租约测试 | 节点凭据、项目范围、资源准入、领取、续租、回收和完成幂等 |
| 节点开发 | `remote_worker.py`、节点测试 | 仅 HTTP 文件传输、独立进程、预算监控、租约丢失停止及结果打包 |
| 主开发 | `cluster_protocol.py`、集群 API、结果接收、Service/CLI 接入、部署文档及集成测试 | 契约与真实闭环验证 |

# 固定工作位移块算法的完整状态恢复

新增 `solver.block.checkpoint_kind='exact_block'`。这条路径保存并恢复自有块逆迭代算法下一次外层迭代所需的完整状态。原有默认值 `subspace` 继续表示给新任务提供初始子空间，两者不能混称。

## 支持条件与调用

必须同时满足：SciPy CPU 后端、`block_shift_invert`、`nearest_k`、禁用自适应工作位移、没有回退 profile、`checkpoint_interval>=1`。实数、复数和已配置的行重排均可用。不支持 ARPACK/JD、不序列化库内存地址或 LU 分解对象。对角解析快捷路径没有块迭代状态。

```python
config = {
    'target': {'k': 2, 'sigma': 0.15},
    'solver': {
        'method': 'block_shift_invert',
        'adaptive_shift': {'enabled': False},
        'block': {'checkpoint_kind': 'exact_block', 'checkpoint_interval': 1},
    },
    'resources': {'threads': 1},
}
run_solver(input_path, config, new_output_dir,
           resume_checkpoint_path=controlled_checkpoint_path)
```

`resume_checkpoint_path` 与原有 `initial_subspace_path` 互斥。接口调用者必须控制快照来源并冻结其真实哈希，不能接受任意外部路径作为已授权快照。数值核心再次验证内容、输入和环境。

## 保存的状态

文件名为 `exact-block.checkpoint.npz`，阶段固定为 `next_iteration_ready`。仅在本轮原问题残差检查、锁定与重启决定全部完成后写入；不会保存半完成的内层求解状态。

- 下一轮实际基、实际锁定掩码、迄今最优已验收值及向量。
- 外层迭代号、完整数值计数、最好残差与停滞次数。
- 已消耗随机数生成器完整状态，含实际重启后状态。
- 固定工作位移、矩阵缩放、当前尝试耗时、已消耗总时间与快照序号。
- 原输入哈希、归一化矩阵哈希、冻结配置、行排列哈希、Python/NumPy/SciPy/BLAS 线程环境、平台、算法源码及实际已加载关键函数摘要。代码摘要递归移除安装文件路径，不因同一可信软件包安装路径不同而任意拒绝。

向量以原输入行序保存。恢复时验证相同行排列，再转为工作行序；保存及载入均不重新归一化或重新正交化下一轮基，以免改变精确算法状态。保存的最优候选另行复算原问题残差。下一轮基必须有限、维度正确并满足正交性要求。

NPZ（多个数值数组的归档文件）只允许明确的四个数组与受限 JSON 元数据，禁止 pickle。先检查压缩成员、展开大小、数组头和内存预算，再加载；校验状态内容摘要及完整控制器字段。临时文件加旧文件的原子替换成本同样受磁盘预算约束，产物清单最后发布。内容摘要用于检测损坏，不能证明作者身份，因此服务还必须验证受控文件的冻结哈希。

## 准确的“精确”范围

恢复的是同一数学实现、输入、配置、排列及浮点环境下的完整下一轮状态。恢复需要重新构造稀疏 LU 分解，该实际分解会增加 `factorizations`；不声称重用了分解内存，也不伪造零恢复成本。

`outer_iterations` 保留累计外层计数，另报 `restored_outer_iterations` 和 `outer_iterations_executed_this_process`。`exact_resume=true` 明确区分子空间热启动；事件历史只包含当前进程新产生的事件，先前历史由原作业保留。已消耗时间计入恢复后的总时间预算，外层迭代上限也不会重置。算法源码或环境改变时拒绝精确恢复；仍可按原有规则另行选择兼容的子空间热启动。

## 可复现验证

```bash
.venv-emsolver/bin/python -m pytest tests/test_numerics_exact_resume.py -q
```

实数及复数重排用例在第3次检查后取消、读取真实快照并恢复。恢复后特征值、保存向量逐位相同，后续逐次残差列表与未中断路径完全相同。另一个远位移用例实际触发停滞重启，核验随机数与重启状态。真实跨进程用例在快照发布后以 `os._exit(9)` 突然退出，再分别运行未中断和恢复工作进程，对照保存向量逐位相等及重新分解计数。反例覆盖不支持组合、暖启动混用、状态篡改、配置改变、非法归档、磁盘超额、时间预算不得重置，以及升级时磁盘新代码与实际已加载旧函数不一致。

## v0.5 跨进程标识规范化

实际加载代码采用明确类型的稳定字段编码，避免把相等常量的对象共享布局当作算法差异；不依赖 marshal 的引用编码。数值库发现列表按完整身份字段规范排序，保留重复库、版本、架构和线程数。发现顺序不影响兼容性，真实字段变化仍拒绝。两个边界均有反例回归，并由最终637项本机与616项Linux全套再次覆盖。

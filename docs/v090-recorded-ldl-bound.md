# 稀疏 LDL 分解过程中的严格残差上界研究

本研究从一个具体成本问题出发：验证完整 `A-LDLᵀ` 的稀疏乘积，工作量可能很大。对于可审查的左看分解，可以在原有数值更新旁记录严格舍入误差，直接累计原矩阵残差的行和上界。**这是尚未接入生产的实数原型，不是已经完成的 GSM 计数证书。**

## 已执行范围

`artifacts/v090-count-reference-research/recorded_ldl.c` 是 SuiteSparse LDL 3.3.2 的研究修改版，使用 SuiteSparse v7.10.1 官方固定版本源码中的左看算法，保留原源码、作者与 LGPL 许可证。修改点是显式 `fma` 更新、逐步外舍入误差和结果界，不改变为带数值主元交换的算法。`recorded_ldl_provider.py` 将输入硬限制为 4096 阶、200000 个输入存储项；默认因子最多 200000 项、估计分解运算最多 2000000 次。它不能被当前配置直接用于 GSM。

本机 macOS arm64 编译并运行过；尚未宣称 Linux、其他编译器、其他浮点环境或完整工业矩阵验证通过。

## 从实际运算推导残差

以下所有身份式都对保存的浮点数所代表的精确实数成立。设第 `k` 行正在构建，列 `i<k` 的当前浮点残量为 `yi`，已保存的对角值为 `Di`，新保存的三角项为 `lki`。定义实际除法缺陷

\[
e_i=y_i-D_i l_{ki}.
\]

即使除法结果不精确，这个缺陷仍是所保存因子的真实代数差。算法中当前残量的更新是

\[
y_j^{new}=\operatorname{fl}(y_j^{old}-L_{ji}y_i).
\]

令该次更新误差为 `rho_ji`，严格定义成“精确的旧值减乘积”与“保存的新值”之差。展开同一行处理过的全部更新，原系数与最终分解乘积的差满足

\[
E_{ik}=e_i+\sum_{j<i}L_{ij}e_j+\sum\rho_{ij}.
\]

因此每次更新 `Yj` 时，只需向该位置的误差累计量加入 `|Lji|*upper(|ei|)+upper(|rho_ji|)`。处理完 `i` 后，该原矩阵非对角残差项的上界为 `Yerr_i+upper(|ei|)`。厄密性在实数情形是对称性，故同一个非对角误差界同时计入原矩阵第 `i`、`k` 两行。

**不再传播 `Yerr_i` 到后续行**：这里不是在包围一个未确定的理想残量；后续实际参与运算的就是保存的 `yi`，它与 `Di*lki` 的代数差已由 `ei` 记录。重复传播会产生不必要的区间扩张；遗漏 `ei` 则会漏掉三角因子除法误差。

对角数值更新为 `Dk_new=fl(Dk_old-lki*yi)`，其真实残差是

\[
E_{kk}=\text{移位减法误差}+\sum\rho_{diag,i}+\sum_i l_{ki}e_i.
\]

所以对角误差累计量只需加入每次对角更新的舍入界和 `|lki|*upper(|ei|)`。矩阵读取边界要求唯一、排序的原系数，浮点散射使用赋值；若允许重复项先浮点求和，就必须另外记录求和误差。本原型直接拒绝重复项，不信任可被手动改写的稀疏规范标记。

这一记录需要与当前正在执行的具体分解算法绑定。**不能把这些公式直接套在 MUMPS 的整数统计或对某些右端的求解残差上，也不能接受调用方自己填写的一串误差界作为证明。**

## 外舍入实现

`fma`（融合乘加）将精确乘积与加数之和只舍入一次；`nextafter` 返回指定方向上相邻的浮点数。本机系统的 `man 3 fma` 与 `man 3 nextafter` 明确对应 ISO/IEC 9899:2011；原始手册文本保存在研究证据目录。

原型要求二进制 64 位格式、53 位有效数、最接近舍入，并运行最小次正规数测试，以拒绝直接把很小非零量冲为零的环境。编译禁用 `fast-math` 和隐式收缩；实际数值更新明确调用 `fma`。

- `upper(|ei|)`：先计算 `abs(fma(-Di,lki,yi))`，再向正无穷移动一个相邻浮点数。
- 更新舍入误差：使用保存结果的一个完整向上 ulp（相邻浮点数之间的间距）作保守界；结果是零或次正规数时仍保留最小正次正规数，避免把下溢误差当成零。
- 非负上界的每次加法、乘法：结果再向正无穷移动一个相邻浮点数，保证累计上界不会因普通舍入而缩小。
- 输入移位减法：每个保存的对角结果也记录一个完整向上 ulp，覆盖原矩阵对角减移位的误差。
- 请求移位不一定能被单个 binary64 精确表示。独立审查的 `1+2^-54` 反例先复现了转换误差遗漏；现保留精确有理 `requested_shift`，将转换到 `effective_shift` 的绝对缺陷严格向上包围后加到每行初始界，并在输出与清单中绑定两者。
- 任一数值因子、误差量溢出或出现非有限值，或遇到无主元交换算法无法继续的零主元，均拒绝。

原型保存每行界 `row_bounds`；其最大值是对称分解残差二范数的保守上界。两组移位的记录式上界若足够小、惯性相同且无零根，可以用 [双移位夹逼判据](v090-count-reference-options.md) 组合。将来生产实现仍需确认可信执行边界、源码 / 二进制绑定、完整进程资源监督和独立复核协议。

## 复现与交叉验证

```bash
.venv-emsolver/bin/python artifacts/v090-count-reference-research/build_recorded_provider.py
.venv-emsolver/bin/python -m pytest artifacts/v090-count-reference-research/test_recorded_ldl_provider.py artifacts/v090-count-reference-research/test_verified_inertia_sandwich.py -q
```

当前 **70 项测试通过**，其中 44 项验证数值提供方，26 项验证独立精确因子检查器。提供方测试包括 20 个带随机置换的不定稠密小矩阵、10 个有随机填充和隐含零项的稀疏小矩阵、约 `2^-1000` 到 `2^1000` 的整体尺度、有理移位转换缺陷、次正规数、算术溢出、零主元、非法规范标记、源码 / 二进制绑定改变与预算拒绝。每个已接受小例子都会把记录式界与**重新计算 `A-LDLᵀ` 的精确有理数残差**比较，而不是只检查数值残差小。

257 阶连通五对角例子的两组显式因子通过独立严格夹逼，普通及固定加权行圆盘均不能在零点给出计数。该例子只证明公式、代码与独立算术在这一范围内一致。对实际 GSM 的填充规模、极小间隙和长时间分解，当前没有记录式证据，不能外推为工业通过。

导出 spike 支持把 `Li/Lx/D/row_bounds` 写入 `.npy` 内存映射文件并生成摘要清单。当前为了交给小型精确检查器，仍构造有界 CSR 因子副本；**不能称为大规模零复制或完整内存外分解实现**。后续需独立的分块读取协议、磁盘配额和清理、取消与硬资源监督。

## MUMPS 5.5.1 的桥接缺口

固定版本 [MUMPS 5.5.1 用户指南](https://sources.debian.org/src/mumps/5.5.1-1/doc/userguide_5.5.1.pdf) 支持内存外求解和内部状态保存，但 `ICNTL(11)` 给出的前向误差与条件数是估计量，不是上述完整分解残差证书。`WK_USER` 只是主数值工作空间的替代存储；Save/Restore 用于恢复求解器内部状态，没有给出独立 `L/D` 交换协议。

固定版本 [C 接口头](https://sources.debian.org/src/mumps/5.5.1-1/include/dmumps_c.h/) 有置换、缩放与工作空间等字段，没有可直接交给独立检查器的规范 `L/D` 输出数组；[Fortran 结构](https://sources.debian.org/src/mumps/5.5.1-1/include/dmumps_struc.h) 则把 `IS/PTRFAC/PTLUST_S/S` 标在内部工作区。当前没有已验证的公开因子桥接。把内部二进制文件猜成某种因子排列，不构成验收证据。

对某些右端求解准确也不能填这个缺口：`H=diag(epsilon,1)` 与 `B=diag(-epsilon,1)` 在 `x=b=(0,1)` 上都有零残差，惯性却不同。要推广记录式证明，需审查并绑定真实运行的分解算法及舍入记录；或取得显式因子后重新做严格乘积验证，不能根据有限个右端求解结果判断全部谱。

开放的 SuiteSparse 提供方避免了私有格式问题，但无数值主元交换，可能在 GSM 近零目标上失败或给出过宽误差界。下一步应先中型留出验证和独立审查，再冻结工业试验协议。**本文件的交付物是一个可证伪、可复现的研究路径，真实工业目标完整性仍待验证。**

## 请求与状态边界

- 列表只请求 `GET /jobs/page?limit=50&project_id=...&status=...&cursor=...`。`ALL` 不发送给后端；状态筛选列出真实合法状态，包含 `TIMED_OUT`。按入库升序展示。
- 项目/状态改变时取消旧列表请求并清空列表和游标；手动刷新开启新的游标快照，便于看到快照建立后的新增任务。自动轮询只刷新首页，保留已加载的后续页面并按任务 ID 去重，不重新加载完整历史。
- 汇总来自 `GET /workspace/summary`，项目总数、矩阵数、任务数、活跃任务数和认证任务数不依赖已加载页面长度。列表分页计数展示当前筛选总数。项目范围同时作用于列表和汇总请求。
- 有活跃任务时列表每 3500 ms 更新；无活跃任务时降至 15000 ms。请求失败保留最后成功状态并显示错误；取消请求不显示业务错误。未向旧路由添加回退或虚构返回。
- 新提交/重试任务使用 POST 的响应对象立即显示详情，即使其还不在已加载的入库升序页面中。结果、报告和诊断的任务选择器提供加载更多入口；对比页也提供加载更多入口。
- 详情先读取任务状态，再读取事件，避免事件查询早于最终事务而错过终态事件。按 `seq` 递增游标读取，每页 200 条，每轮最多 5 页；仍有后续页时 150 ms 后续读。
- 事件通过 `Map` 按 `seq` 去重，再保留最新 1000 条。页面持续显示窗口上限，发生裁剪时明确提示，并提供 `events.jsonl` 完整下载入口。
- 终态先排空事件，再读取结果，成功后停止详情轮询。`FAILED`、`CANCELLED`、`TIMED_OUT` 的结果 404/409 视为正常无结果；`SUCCEEDED`/`PARTIAL` 的结果错误以及其他 HTTP 错误继续报告并重试。
- 切换任务/项目、刷新或卸载时使用 `AbortController`（浏览器请求取消控制器）取消旧请求和定时器，并在发布响应前核对任务和取消状态。事件游标与结果不跨任务复用。
- 原有 12 个导航与配置编辑、矩阵处理、数值展示、比较、基准、诊断、报告、系统、审计及帮助工作流入口保留。

## 已知边界

- 上述单元测试使用真实模型逻辑与受控请求响应，不等价于真实 HTTP 或浏览器端到端验证；Hook 的实际 React 调度、页面布局和全部 12 条业务路径仍由主开发在新后端启动后检查。
- 旧运行中的后端若尚未重启，不具备新增路由，页面会按实际错误提示。这里没有声称旧进程已经通过联调。
- 自动刷新保留的历史页可能在下一次手动刷新前包含旧状态；这符合“只轮询首页”的请求边界。手动刷新重置分页快照，状态/项目筛选始终由服务端执行。
- 首次打开事件很多的任务仍需逐页追赶，但每轮请求数和前端保留的事件数量均有上限；完整证据由下载入口获取。

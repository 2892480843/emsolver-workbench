# v0.8 数值架构与数据结构

本轮保持 FastAPI 模块化单体、SQLite schema 2、独立数值工作进程及父进程资源监督。没有数据库迁移；旧任务、输入和旧版本归档保留。新增能力集中在预条件组件、停止控制及独立证明，三者的结论分别记录。

## 调用链与职责

`resolve_config → algorithm_plan / estimate_resources → SciPyBackend → solve_correction → 原矩阵验证 → 独立目标认证 → 原子产物发布`。

- `preconditioning.py` 管理显式 v1/v2 策略、构建预检、一次分解和应用成本。v2 先固定四次对称均衡，再进行固定 1% 行和对角补偿；这些操作只用于近似逆，不替换原问题。
- `correction.py` 在每个外层候选块上构造一次约束逆缓存，全部内层修正列复用。GMRES（广义最小残差法，迭代求解修正方程）仍以原修正算子的双精度残差判断通过。
- `accuracy.py` 统一精确认证已有的值精度预算，并提供浮点精度提示。只有实际有界认证因 `candidate_value_enclosure_too_wide` 拒绝，才启用提示。几何不适用、计数失败或资源不足不触发精度继续迭代。
- `independent_counts.py` 在原有均匀圆盘之外提供精确二次幂带权圆盘。权重只依赖原矩阵；正对角相似变换保持特征值，半径按精确有理数计算。原矩阵残差、候选重数、秩及整体子空间角度全部复验。
- `core._certify` 只在原圆盘方法的明确几何拒绝后尝试带权方法；预算、无效候选或数量错误不绕过。最终认证重新使用原输入，停止控制中的探测结果不直接发布为证书。

## 关键数据结构

| 数据 | 生命周期与上界 | 用途 |
|---|---|---|
| 原始/缩放 CSR 稀疏矩阵 | 一次求解；始终稀疏 | 保存原问题并执行稀疏乘法 |
| v2 缩放向量 D | n 个 float64 系数 | 在原坐标应用近似逆 |
| 不完全分解内部因子 | 一次求解复用 | 不导出 L/U 副本；记录实际 `factor.nnz` |
| 候选 Q 与 Z=BQ | 每个外层更新；最多 `subspace_max` 列 | 缓存约束逆，避免每个内层操作重复求解 Q |
| 小 Schur 矩阵 S=Q*Z | 最多 m×m，m=`min(n,subspace_max)` | 归一化后分解；条件数超过 1e12 明确拒绝 |
| 带权指数 | n 个 int16，小端哈希 | 使用二次幂比例，JSON只存策略、范围及摘要 |
| 数值有效候选 `best` | 最多受限目标列数 | 迭代/重启耗尽仍可给出 PARTIAL；不宣称强杀后必能导出 |
| 事件与计数器 | 沿用有界事件存储 | 探测成本、提示次数、分解、缩放及约束求解成本可追溯 |

v2 资源估计除旧 ILU 工作集外，增加均衡稀疏临时数据、缩放/对角向量、前后两轮 Q/Z 缓存可能并存及小矩阵工作空间。规划中的 `fill_factor` 不是峰值内存保证，父进程继续监督整个进程树的实际内存和墙钟时间。所有原生库调用都可能在 Python 检查点之间运行。

## 停止与认证语义

1. 每次外层以原矩阵计算候选残差；达到数值门槛先保留候选。
2. 请求完整性且属于一般稀疏路径时，全部目标候选数值合格后执行一次有界精确探测并记录时间/原因。
3. 仅值包围过宽时继续迭代，浮点提示使用已有精确精度预算的八倍裕量；提示不是数学证明。
4. 达到提示或迭代预算退出后，输出阶段重新独立验证。无法证明目标完整性时仍为 `UNVERIFIED / PARTIAL`。

各证明方法有自己的默认 5 秒及位长/运算预算，串行尝试不应描述为总共只用 5 秒；任务父进程及独立验证父进程的整体限制仍有效。带权预扫描先检查 `n+nnz` 的运算下界，超过默认 500 万即拒绝。589446 阶、21758924 非零元的完整 GSM 矩阵超出此带权默认预算，不能据本扩展宣称它能获证。

## 验证边界与依据

新方案在独立合成训练及保留测试中选择，固定后再试公开工业输入。小规模稠密参考只用于测试；生产路径不稠密化原矩阵。合成算例、二维教学模型、真实工业模型分别标识，性能比较必须保持输入、目标、精度及资源一致。

数学推导、固定规则、对照及局限见 [预处理 v2](preconditioning-v2.md)；精确带权证明见 [独立目标计数](independent-target-counts.md)。实际测试和工业结果统一登记在 [本轮交付](v080-delivery.md)，不将策略实现当作工业验收通过。

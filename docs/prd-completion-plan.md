# 完整PRD实施与验收计划

目标：逐项实现原PRD的66项需求并保留可复现证据，不通过删除要求或放宽验收来制造“全部完成”。当前环境为macOS arm64；Linux、工业数据及可选加速后端另记录真实验收条件。

架构选择：继续模块化单体，复用SQLite、独立计算进程和既有API。相较于新建外部账号服务、分布式队列和数据库，这能保留本地离线部署及当前数据。项目策略、导入任务、算法接口、知识与建议效果分别拆模块，通过窄接口集成。

## 分阶段闭环

1. 项目及数据治理（F01/F04/F10/F12/F23/F31/F64）：角色身份与项目成员权限、可追踪拒绝审计、配额/优先级/保留策略、流式上传与可取消独立导入进程；旧单用户模式保留。
2. 输入与数值边界（F02/F07/F08/F11/F19/F21/F22/F24至F30/F34/F37）：规范化记录、派生三角资产、行非零分布、资源分项估计、置换及回映射、标准后端协议和有证据的替代算法。未提供观测的后端保持不可用指标，禁止伪造精确续算。
3. 解释与效果（F40/F53至F58）：版本化规则及知识、可选本地模型的受限解释与确定性降级、不可变建议效果记录、来源/代码/依赖/环境及复现命令报告。
4. 评测与交付（F41/F44/F47至F52/F59至F63/F65）：隔离参考及跨运行模式对齐、冻结开发/保留协议、完整材料语义检查、公开包脱敏扫描、目标平台运行与缺文件恢复策略。
5. 集成验收：原有268后端及30前端回归、新功能正反例、浏览器真实完整流程、旧数据保留、独立审查、更新66项验收登记与交付包。

## 明确约束

- 修改任何实验参数生成新快照；取消和失败不能变为认证成功。
- 数值结果仍以原始问题双精度独立验证；稀疏原矩阵禁止全尺寸稠密化。
- 角色权限作用于API和共享令牌用户，不冒充操作系统文件隔离。
- 开源本地模型为可选配置；不未经许可下载模型或依赖其完成求解。
- 无物理自由度映射不生成器件场图；无目标计数证据不认证全谱。
- 全部完成要求每项有实际实现及验收证据；需要外部条件的验收单独列阻断，不能标记通过。

## 接口契约

项目字段：`classification=public|internal|confidential`，`members=[{subject,role:viewer|analyst|admin}]`，`policy={storage_limit_gib,max_queued_jobs,priority,retention_days}`。默认4096GiB/100排队/0优先级/30天，保留旧实例行为。项目使用量区分逻辑输入、实际输出和活跃任务保留的输出预算。

`GET /projects?q=`、`PATCH /projects/{id}`、`GET /projects/{id}/usage`、`GET /identity`。

导入：`POST /imports` multipart流式接收至私有临时文件，返回任务；`GET /imports?project_id=`、`GET /imports/{id}`、`POST /imports/{id}/cancel`。传输中客户端中止清理文件；校验在独立可终止进程，状态为QUEUED/RUNNING/CANCELLING/SUCCEEDED/FAILED/CANCELLED。仅成功后注册资产。

`POST /matrices/{id}/derive {triangle,name?}`新建可追溯三角派生资产。

`GET /knowledge?q=`、`POST /diagnostics/explain {job_id?|config}`、`GET /advice/effects?source_job_id=`、`GET /advice/effects/{id}`、`POST /advice/effects/{id}/link {job_id}`；采用来自任务的建议时返回`effect_id`。
